# ClueShelf 第一版規劃紀錄

狀態：需求訪談中，尚未開始實作。以下區分已確認方向與待決定事項。

## 已確認方向

- 先完成本地可用版本，保留未來邀請制產品上線的路徑。
- Python 後端、Next.js 前端、SQLite。
- 使用者目前以 YouTube、Instagram、Threads 為主要來源；只處理主動收藏。
- 收藏入口以連結為主，無法讀取時允許補作者內文。平台批次讀取須驗證。
- 繁體中文與日文為主要搜尋語言。
- 台灣、日本、韓國的餐廳、景點、演唱會地圖為主要特色。
- 食譜、音樂、技術、求職與語言學習保留基本分類與搜尋需求。
- 優先本地或免費工具；本機 RTX 3060 12GB 可供測試。
- 希望成果兼具實用性與 AI 應用／全端職缺作品集價值。

## 第一輪決定

1. MVP 包含三平台連結收藏、補作者內文、AI 分類、文字與語意搜尋、地點確認與地圖；其他主題使用共用列表。截圖辨識、歷史匯入與學習路線延後。
2. AI 分類與標籤直接套用且可修改；主題採固定選項，細部標籤允許新增。地點須確認後才上圖。
3. 接受下載本地模型；以 Ollama 執行分類，語意搜尋也在本機執行。

## 第二輪決定

1. 接受免費外部地點查詢；找不到時可在地圖手動選點。查詢採使用者主動觸發與結果快取，提供者須先測試台日韓覆蓋率。
2. 同一使用者的同一平台內容依平台內容 ID 去重，重複加入時回到原收藏，可補充內容或重新整理。不同貼文仍各自保存，可指向同一地點。
3. 人工修改優先，AI 重新處理不覆寫人工修改欄位；使用者可明確重設欄位，交由 AI 重新判斷。

## 第三輪決定

1. 主題初始集合：食譜、餐廳、旅遊、音樂、程式、語言學習、求職、活動、其他；可複選。演唱會公告屬於活動與音樂，演唱會影片屬於音樂。其他類內容允許 AI 提議新主題或整合主題，提議如何套用待下一輪確認。
2. 提供手動清單與儲存搜尋條件的動態清單，不包含旅遊行程自動編排。
3. 本地版為單人開發帳號、免登入、預設僅限本機存取；資料保留使用者歸屬。
4. 驗收採使用者自願提供的 60 筆收藏，每平台 20 筆，涵蓋繁中、日文與台日韓地點；讀取失敗可補內文完成整理，主要分類至少 80% 正確，20 個預先定義搜尋問題至少 16 個於前五筆命中，地點候選確認與手動定位皆可完成；重複收藏、處理失敗及程序重啟不遺失已保存內容。

## 第四輪決定

1. AI 新增或合併主題前，須提出理由與受影響收藏，由使用者核准後套用；一般收藏分類仍自動進行。
2. 合併前預覽受影響收藏與動態清單，確認後統一更新；保留舊名稱作為搜尋別名。人工修改若受影響也須列入預覽，本次明確確認才允許更新。
3. 全庫主題檢查由使用者按下「檢查分類建議」觸發；一般分類遇到未知內容可留下新主題提議，不逐筆重新分析整個收藏庫。

## 第五輪決定

1. 只讀公開可取得的標題、作者內文與中繼資料，失敗時允許補作者內文；保存文字與來源連結，不下載完整影片，不收取平台登入憑證。圖片失敗用平台圖示代替。
2. 不猜測不完整日期，資料標為待補充；多場活動分開保存並共用來源收藏。場館確認即可上圖，完整日期才參與日期篩選。
3. 提供手動完整備份、還原與 JSON 匯出。備份包含 SQLite 與附件，不含模型檔。刪除收藏須確認，移除搜尋資料及無其他引用的附件，不連帶刪除共用地點。

## 訪談狀態

## 第二階段追加確認

- YouTube 作者內文對應影片說明，標題預設原始標題，可選 AI 潤飾；IG 對應 caption，Threads 對應正文。
- Threads 例外加入留言：正文與留言分開保存並一起分析。實際取得最多 50 則頂層留言，選按讚前 10 則；缺少讚數標為可見留言。
- 不收取平台憑證；讀取限制時保留正文並允許手動貼留言。
- 使用者已授權依 pstack poteto-mode 實作，small／inherit-parent 設定沿用。
- YouTube 實作使用受限制的公開 HTML metadata，而非原提案的 yt-dlp；原因是維持一致的目的 IP、跳轉與大小限制。不下載完整影音。
