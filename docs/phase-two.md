# 原文讀取與本地 AI 整理

## 資料流程

貼連結先保存，再由一筆版本化工作依序讀取平台原文與呼叫本地模型。來源與分析各自保存狀態，模型失敗不會清除來源。重新處理保留人工修正。

- YouTube 讀取公開 player metadata 的標題及說明，不讀留言、不下載影片。
- Instagram 依內容代碼讀取作者 caption，不讀留言。
- Threads 解析分享網址，讀取正文與可確認屬於原貼文的頂層回覆。最多取樣 50 則，再依可取得的讚數保留前 10 則。缺少讚數則標為可見留言。無法公開取得時允許手動補充。
- 公開 HTML 優先，必要時使用隔離、未登入的 Chromium。所有 HTTP 目的地須通過來源網域及公開 IP 檢查，連線釘選該 IP，限制跳轉、時間及大小，封鎖媒體、Service Worker 和 WebSocket。
- Python 直接呼叫 Ollama /api/chat，Qwen3 4B 以 JSON Schema 輸出，Pydantic 驗證後才保存。

## 來源與人工修改

source 保存原始資料，author_text 是用於整理的有效正文，人工修改後不再被讀取器覆寫。Threads 手動留言另存 manual_comments。分析快照包含模型、時間與輸入版本。

YouTube 預設顯示原標題。其他平台沒有獨立標題時由模型根據正文命名。AI 標題是可選的顯示來源，不會改寫來源原文。人工標題優先，除非使用者明確切換來源。

分享網址解析後若命中既有收藏，保留草稿並標記 duplicate_of，不覆寫任一筆人工內容。草稿仍可瀏覽，提供開啟原收藏的按鈕。

模型使用最多 2,500 字正文、300 字原標題，以及每則最多 100 字的留言節錄。完整來源仍保留，使用節錄時介面顯示提示。這是本地 8K context 的起始限制，長文分段整合留到後續。

實測發現 4B 模型會對短文俚語產生沒有原文依據的解釋。正文少於 80 字且沒有留言時，摘要直接保留原句並標示來源；標題與分類仍由模型產生。其他 AI 摘要品質仍須對照原文評估。

## 背景工作

一筆工作完成讀取及分析，不建立同版本的多個工作，因此保留 save_id 與 version 的唯一性。每 10 秒續租一次，租約 60 秒。續租和提交均檢查 token、未過期狀態及收藏版本。

網路讀取與模型推論在 SQLite 交易外進行。舊工作不能覆寫新版收藏。失敗重新讀取不會清掉上次成功的來源，分析失敗則保留並標示舊結果。

遷移前由 scripts/migrate.py 保存 SQLite 備份。既有非空標題和正文視為人工內容，不自動重新讀取。

## 介面

POST /api/v1/saves/{id}/read 重新讀取並整理，POST /analyze 只整理目前內容。兩者要求 version。POST /title 以 version 和 mode 選 original 或 ai。PATCH 可補 manual_comments，但僅適用 Threads。

來源快照、分析與獨立處理狀態包含在收藏回應。健康端點表示功能已接線，不保證 Ollama 或外部平台當下可用。

## 真實來源檢查

scripts/probe_sources.py 只探測使用者提供的三個公開連結，不修改收藏。一次完整檢查取得 YouTube 1,666 字說明、IG 535 字作者內文、Threads 26 字正文。Threads 曾提供回覆樹，但不同匿名回應可能省略；留言未取得必須顯示部分成功，不保證每次可讀。

完整測試及實際模型結果另記於 implementation-log.md。私人收藏與測試來源內容不提交公開版本庫。
